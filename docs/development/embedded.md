# 嵌入式开发规范

## 1. 适用范围与规范读取

本规范适用于裸机、RTOS、MCU、SoC、驱动、固件、Bootloader 和板级支持包开发。

涉及嵌入式任务时，必须先读取本规范，并按范围读取 C++、CMake、并发、日志、验证、安全、接口和发布规范。芯片、SDK、RTOS、编译器和外设 API 必须以项目锁定版本和官方资料为准，不得凭记忆猜测。

本规范不代替汽车、医疗、航空或工业安全等领域的强制标准；若项目有认证或客户标准，必须记录标准、版本、适用范围和偏差处理方式。

## 2. 分层与目录

推荐按以下边界组织：

```text
app/          应用与业务状态机
services/     设备服务与业务适配
middleware/   协议、存储与调度
drivers/      外设驱动
hal/          硬件抽象层
bsp/          板级初始化、引脚、时钟与启动配置
bootloader/   启动、升级与回滚
tests/        主机、目标板和验收测试
```

- 应用层不得直接访问寄存器、GPIO、DMA、RTOS 内核对象或芯片 SDK。
- 驱动只负责硬件访问和状态转换，不承载业务规则。
- HAL 提供可替换、可模拟的接口；硬件差异集中在 BSP 和驱动层。
- 依赖方向只能由上层指向下层，禁止驱动反向依赖业务模块。

## 3. 资源预算与内存

- 设计阶段建立 Flash、RAM、栈、堆、DMA 缓冲区、CPU 占用和功耗预算。
- 链接脚本、内存布局和 map 文件必须纳入构建产物检查。
- 默认使用静态或固定容量分配；启动后原则上禁止无界动态分配。
- 必须使用堆时，说明最大容量、生命周期、失败策略和碎片风险。
- 禁止递归、可变长栈对象和无上限容器；数组、队列和任务数量必须有上限。
- 每个任务配置独立栈，并在测试中检查栈水位和溢出保护。
- DMA 缓冲区满足对齐、地址范围、缓存一致性和生命周期要求。
- 超出资源预算必须阻止发布或形成明确例外记录。

## 4. 实时性与时序

- 为周期任务、中断、通信和启动流程定义截止时间、允许抖动和最大执行时间。
- 对关键路径测量最坏情况执行时间、调度延迟、中断延迟和队列等待时间，不以平均耗时代替实时性证明。
- 高优先级任务不得执行无界循环、阻塞 I/O、不可控日志或长时间临界区。
- 临界区、关中断和锁持有时间必须有上限；临界区内禁止调用未知耗时函数。
- 使用优先级继承、优先级天花板、单一所有者或消息传递避免优先级反转。
- 周期任务使用单调时间基准；超时、降级、丢帧和资源不足必须有确定行为。

## 5. 中断、线程与任务

ISR 只确认中断、读取必要状态、保存最小数据并投递事件，随后尽快退出。ISR 禁止动态分配、阻塞等待、获取不可立即获得的锁、复杂计算、慢速外设、协议解析、日志 I/O 和业务流程。

- 复杂处理转移到任务、工作队列或下半部，并定义事件丢失、合并和背压策略。
- 任务数量、优先级、栈大小、队列容量和周期必须有记录。
- 任务之间优先使用有界队列、事件或消息传递，减少共享可变状态。
- 不创建脱离生命周期管理的 detached 任务；每个任务必须有退出、取消、超时和回收路径。
- 关闭、升级或复位前停止接收新工作，并等待或取消已有任务。
- 遵循并发规范：线程数、队列容量和重试次数必须有上限。

## 6. 硬件抽象与驱动

- 外设初始化、配置、读写、错误和复位路径封装在驱动或 HAL 中。
- 寄存器访问使用统一类型、`volatile` 语义、内存屏障和读改写策略。
- 不使用未经说明的魔数；寄存器位、时钟、引脚和中断号使用命名常量或配置。
- 驱动接口说明调用上下文：线程、ISR、初始化或低功耗唤醒。
- 明确设备状态：未初始化、就绪、忙、错误、恢复中和已停止。
- 外设异常、超时、拔插、时钟切换和电源变化必须可恢复或进入安全状态。
- 硬件依赖应可由 Mock、仿真器或测试适配层替换。

## 7. 启动、看门狗与故障恢复

启动流程明确记录：复位原因读取 → 时钟与内存初始化 → 安全默认状态 → 基础自检 → 驱动初始化 → 通信与存储恢复 → 应用启动 → 看门狗监管。

- 启动早期将执行器、继电器、功率和通信引脚置于安全默认状态。
- 初始化失败不得宣称系统就绪，应进入降级、维护或安全停机状态。
- 看门狗只能在系统健康检查通过后喂狗，禁止无条件喂狗掩盖死锁。
- 记录复位原因、固件版本、启动阶段和最近一次故障摘要。
- 任务卡死、栈溢出、堆损坏、非法访问、欠压和时钟异常必须有恢复策略。
- 复位循环限次并能进入安全或维护模式；关键故障信息使用带 CRC 和版本的持久化区域保存。
- 关键操作具备幂等性，避免复位后重复执行造成设备或数据损坏。

## 8. 持久化与掉电安全

- 持久化数据包含版本、长度、校验和必要的兼容标识。
- 配置更新使用双备份、日志式提交或原子交换，不能覆盖唯一有效副本后再假设写入成功。
- 明确擦除、写入、校验和提交各阶段掉电时的恢复行为。
- Flash、EEPROM 和 FRAM 写入考虑擦写寿命、磨损均衡和写入频率。
- 高频循环不得直接写非易失存储；采用缓存、批量提交或变化检测。
- 数据格式使用固定宽度类型和明确字节序，禁止直接持久化含指针或编译器布局依赖的对象。
- 格式变化同步更新版本迁移、测试和文档。

## 9. 通信与协议

- 所有外部输入不可信；校验长度、版本、类型、序号、范围、CRC、权限和状态。
- 协议帧定义边界、最大长度、超时、重试上限和错误恢复规则。
- 解析禁止无界缓冲区、无限重试和阻塞等待。
- 丢包、重复包、乱序、半包、非法包和连接断开有确定处理。
- 收发缓冲区有容量上限和背压；DMA、零拷贝和缓存共享经过生命周期、对齐和一致性验证。
- 关键命令使用认证、序号、幂等键或防重放机制。
- 协议变更同步更新接口文档、兼容矩阵、测试数据和迁移说明。
- 记录通信状态、错误码、重试和超时，但不得记录完整敏感载荷。

## 10. 功耗与设备状态

- 明确运行、空闲、睡眠、深睡、唤醒和故障状态的进入与退出条件。
- 低功耗前停止或挂起外设、任务、DMA 和通信，并保存必要上下文。
- 唤醒源可追踪；唤醒后重新确认时钟、引脚、电源和外设状态。
- 功耗测量记录固件版本、板卡版本、供电条件和测试状态。
- 不能为省电而牺牲看门狗、故障记录和安全输出。

## 11. 安全与固件更新

- 根据设备风险采用安全启动、签名校验、固件完整性校验和版本回滚保护。
- 密钥存储在受保护区域，不写入日志、明文配置或普通通信报文。
- 生产环境关闭或限制调试接口、未授权下载和危险命令。
- 升级包校验设备型号、硬件版本、版本号、签名和完整性。
- 升级采用 A/B、回滚分区或可验证的断电恢复方案；失败、断电、版本不兼容和签名错误进入可恢复状态。
- 记录安全事件和升级结果，但不得记录密钥、令牌或完整敏感数据。

## 12. 日志、诊断与故障回溯

- 遵循 [日志与终端输出](logging.md)，目标是还原“何时、哪个模块、在什么状态下、执行了什么、得到什么结果”。
- ISR、关键实时路径和高频循环不得同步输出日志。
- 使用有界环形缓冲区、异步输出、级别过滤和采样，避免日志破坏实时性。
- 发布固件默认关闭高成本 `trace` 和 `debug`，保留必要的 `info`、`warn` 和 `error`。
- 故障日志包含固件版本、板卡标识、复位原因、错误码、阶段、时间基准和关键状态摘要。
- 日志丢弃、缓冲区满和输出设备故障必须可统计；不得写入密钥、完整协议报文、指针地址或未经授权的内存内容。
- 崩溃转储、断言和 HardFault 记录使用固定格式、校验和和导出工具。

## 13. 测试与验证

至少建立：主机单元测试、HAL/驱动替身测试、目标板测试、硬件在环测试、系统验收测试和压力/耐久测试。

必须覆盖正常、边界、非法输入、资源不足、ISR 与任务并发、竞态、乱序、丢事件、优先级反转、超时、取消、看门狗复位、掉电、升级中断、回滚、栈溢出、堆耗尽、队列满、DMA 错误、外设失联、日志脱敏和崩溃转储。

测试不得依赖固定睡眠或偶然调度；优先使用硬件信号、事件、屏障、模拟时钟和确定性输入。验证报告记录实际命令、硬件、固件版本和环境。

## 14. 构建、烧录与发布

- 固定编译器、SDK、芯片头文件、链接脚本和构建工具版本，记录目标型号、优化级别、宏定义和构建配置。
- 遵循 CMake 规范，生成并审查 ELF、HEX/BIN、map、符号和版本清单；检查二进制大小和内存预算。
- 发布产物可追溯到 Git 提交、工具链、配置、板卡和构建时间；不包含调试密钥、开发配置和未验证补丁。
- 烧录前确认设备型号、硬件版本、电源条件、擦除范围和目标固件；命令、参数、校验和失败处理可复现。
- 默认禁止无确认的全片擦除；保留校准、序列号和持久化区域时明确范围。
- 发布包含固件、签名或校验值、版本清单、兼容矩阵、升级和回滚说明。
- 发布前验证启动、通信、核心功能、升级、回滚和复位；现场升级具备断电恢复、失败回滚和版本拒绝机制。

## 15. Review 检查项

嵌入式 Review 至少检查：

- 资源预算、栈/堆/队列上限、链接布局和固件大小。
- ISR 是否短小、无阻塞、无动态分配和无高成本日志。
- 实时性、优先级、锁、临界区、超时、取消和任务回收。
- HAL/驱动边界以及应用是否越权访问硬件。
- 初始化、复位、看门狗、故障恢复和安全默认状态。
- 持久化掉电安全、寿命、CRC 和版本迁移。
- 输入校验、协议边界、权限、固件签名和回滚。
- 日志脱敏、限频、故障上下文和崩溃回溯。
- 主机、目标板、硬件在环、故障注入和耐久测试证据。
- 构建可复现性、警告、静态分析、固件大小和发布产物。

每次 Review 依据 [代码 Review 规范](code-review.md) 生成 `docs/review/YYYY-MM-DD-code-review-主题名.md`，列出已确认问题、潜在风险、证据、严重性和未覆盖范围。
