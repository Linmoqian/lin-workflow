# 具身智能与机器人系统规范

## 1. 适用范围与规范读取

本规范适用于机器人、具身智能、传感器融合、运动控制、规划、执行器、仿真和人机协作系统。

涉及机器人任务时，先读取本规范，并按实现范围读取 [C++ 开发](cpp.md)、[嵌入式开发](embedded.md)、[并发与线程](concurrency.md)、[日志与终端输出](logging.md)、[验证](verification.md)、[代码 Review](code-review.md) 以及具体平台、协议和接口文档。使用第三方机器人框架、硬件 SDK 或设备 API 时，以项目锁定版本和官方资料为准。

本规范不替代适用的机械、电气、功能安全、医疗或人机协作法规。涉及人员、动力设备或高能量执行器时，必须先完成安全评估并遵循 [安全工程规范](safety.md)。

## 2. 系统分层与依赖

推荐按以下职责分层：

```text
任务与应用层       目标、任务状态机、用户交互
规划与行为层       路径、动作、行为树或策略
状态估计层         传感器融合、定位、姿态、健康度
控制层             轨迹跟踪、闭环控制、约束与限幅
设备服务层         传感器、执行器、标定、诊断
HAL/驱动/BSP       总线、时钟、中断、硬件访问
安全监督层         急停、保护停机、限位、故障响应
```

- 上层通过版本化接口调用下层，不得绕过安全监督层直接驱动执行器。
- 驱动和设备服务不得承载任务策略；规划器不得直接访问寄存器、GPIO 或 DMA。
- 安全监督可以否决上层命令，但普通业务模块不能关闭或绕过安全监督。
- 每层明确输入、输出、时序、所有权、线程模型、错误和关闭行为。
- 设备、仿真和回放使用同一套上层接口；平台差异集中在适配层。

## 3. 单位、坐标系与时间

- 优先使用 SI 单位；接口、变量、消息和文档明确单位，角度必须明确使用弧度或角度。
- 每个位姿、速度、力和轨迹必须标明参考坐标系、方向约定、右手或左手系及原点定义。
- 坐标系名称稳定且全局唯一；变换树必须无环，外参、内参和标定版本可追溯。
- 传感器数据至少区分采样时间、设备时间、接收时间和处理时间；控制超时使用单调时钟。
- 时间同步方案、时钟漂移、最大允许偏差和丢失同步后的行为必须记录。
- 不得用接收时间冒充采样时间，不得在未说明的情况下混用坐标系或单位。

## 4. 传感器与状态估计

- 传感器接口定义采样率、时间戳、单位、坐标系、精度、量程、有效期和质量状态。
- 每帧数据带有设备标识、序号、时间戳、校准版本和有效性标记；禁止用默认值静默替代无效数据。
- 明确处理丢帧、重复、乱序、延迟、饱和、越界、遮挡、漂移、断连和校准失效。
- 融合前检查时间对齐、坐标变换和数据质量；不确定性、置信度或协方差不能被无依据地省略。
- 传感器冲突、健康度下降和估计失稳必须触发降级、重定位、保护停止或人工接管中的确定行为。
- 标定数据与设备、固件、传感器序列号、时间和工具版本绑定，不覆盖唯一有效标定。

## 5. 执行器与控制回路

- 执行器接口明确位置、速度、加速度、力、力矩、电流、温度、限位和故障状态的单位与范围。
- 控制器定义周期、截止时间、最大抖动、允许延迟、稳定性假设、饱和处理和失控行为。
- 所有目标值经过安全监督统一限幅；速度、加速度、力、力矩、功率、工作空间和温度限制必须可配置且有安全默认值。
- 反馈数据过期、丢失、异常或与命令不一致时，不得继续输出未受限命令。
- 控制循环内禁止阻塞 I/O、无界分配、异常传播、慢速日志和不可控外部调用。
- 执行器通信中断、看门狗超时、控制器失稳或急停时，按设备定义进入安全状态；不能仅依赖上层进程退出。
- 控制器、规划器和安全监督的周期、优先级和数据交换方式必须记录并可测量。

## 6. 规划、行为与任务状态机

- 任务、行为和动作使用显式状态机；状态、进入条件、退出条件、超时、取消、重试和恢复路径完整定义。
- 规划输入、约束、目标函数、地图或场景版本可追溯；规划失败不得输出未验证或过期轨迹。
- 动作命令包含版本、有效期、目标坐标系、约束和幂等标识；过期或重复命令有确定处理。
- 任务恢复必须从当前真实设备状态重新确认，不假定进程重启前的内存状态仍然有效。
- 人工接管、暂停、恢复、取消和重规划的优先级高于普通任务动作，并在日志中记录原因和操作者来源。

## 7. 并发、消息与实时性

- 默认采用最简单的单线程或事件顺序；只有目标指标需要时才引入线程、进程、协程或并行算法，并以基准证明收益。
- 传感器、规划、控制和设备任务的队列、缓存、重试和并发数必须有界；满载时采用明确丢弃、降采样或拒绝策略。
- 消息包含序号、时间戳、来源、版本和有效期；不得依赖偶然调度顺序。
- 共享状态优先使用消息传递和不可变快照；锁范围最小，不跨等待持锁。
- 高优先级控制路径不等待低优先级任务；必要时使用优先级继承或单一所有者避免优先级反转。
- 任务取消、超时、设备断开和系统关闭必须停止接收新工作，并回收线程、句柄、队列和硬件资源。

## 8. 日志、回放与可观测性

- 遵循 [日志与终端输出](logging.md)，关键操作至少记录开始、阶段、结束状态、耗时、错误码和关联 ID。
- 记录传感器健康度、控制周期、队列延迟、执行器状态、规划结果和安全状态变化，但不得在实时循环同步写日志。
- 记录或导出回放所需的时间戳、坐标系、设备标识、配置、模型、代码提交和数据版本；敏感数据遵循脱敏规则。
- 日志、传感器记录和控制命令必须能区分采样时间、发送时间、接收时间和执行时间。
- 回放应能重建关键状态转换；不能回放的硬件依赖、随机因素和未记录配置必须在报告中说明。

## 9. 仿真、实机与安全边界

- 仿真、硬件在环和实机使用同一接口契约，但不把仿真通过视为实机安全或功能通过。
- Sim2Real 差异必须记录，包括动力学、传感器噪声、延迟、通信丢包、执行器误差、环境和标定差异。
- 首次实机运行遵循低能量、低速度、受限空间、人工急停可用和逐级放量原则。
- 未验证的规划、策略、模型和控制参数不得直接部署到有人环境或高能量设备。
- 故障注入、急停、保护停机、通信中断和传感器失效遵循 [安全工程规范](safety.md) 与 [仿真与 HIL 规范](simulation.md)。

## 10. 测试与验收

至少覆盖：

- 单元测试：坐标变换、单位转换、状态机、限幅、轨迹和错误处理。
- 集成测试：传感器、估计、规划、控制、设备服务和消息协议。
- SIL/HIL/实机测试：时序、延迟、丢帧、故障恢复、急停和资源边界。
- 回放测试：固定输入、随机种子、配置、模型和代码提交下结果可比较。
- 长时间测试：温度、功耗、内存、队列、日志、漂移和任务回收。

验收记录硬件、固件、软件、模型、场景、标定、工具链、命令、指标、失败样本和未覆盖范围。不得用固定睡眠或偶然调度替代事件、屏障和确定性时钟。

## 11. Review 检查项

Review 具身系统时至少检查：

- 分层、依赖方向、接口版本、单位、坐标系和时间戳是否明确。
- 传感器质量、标定、融合不确定性、丢帧和异常数据是否有确定处理。
- 控制周期、延迟、限幅、反馈过期、执行器失控和安全监督是否覆盖。
- 状态机、取消、人工接管、恢复、重试和幂等性是否可验证。
- 并发上限、队列背压、锁、优先级、实时路径和关闭回收是否安全。
- 日志是否可关联回放，是否记录关键状态而未阻塞实时路径。
- SIL、HIL、实机、故障注入和耐久测试是否有证据。
- 每次 Review 依据 [代码 Review 规范](code-review.md) 生成日期命名报告，区分已确认问题、潜在风险和未验证范围。
