# 单位、坐标系与时间规范

## 1. 适用范围与原则

本规范适用于生物数据、传感器、机器人、嵌入式、前后端接口、模型输入输出和实验报告中的数值、姿态与时间。

单位、坐标系和时间戳是接口契约的一部分。任何无法明确解释单位、参考系或时间语义的数值不得进入跨模块接口、数据库、模型或控制环路。

## 2. 单位约定

项目默认采用 SI 单位；边界协议、设备原生单位或业务单位不同于 SI 时，必须在接口文档、字段名和转换代码中明确说明。

| 物理量 | 默认单位 | 约束 |
| --- | --- | --- |
| 长度 | `m` | 不使用未说明的 `mm`、`cm` |
| 质量 | `kg` | 质量与重量不可混用 |
| 时间间隔 | `s` | 接口整数必须写明 `ms`、`us` 或 `ns` |
| 角度 | `rad` | 用户界面可显示度，但边界转换为弧度 |
| 角速度 | `rad/s` | 明确参考坐标系 |
| 频率 | `Hz` | 与周期 `s` 分开命名 |
| 温度 | `degC` 或 `K` | 同一接口不得混用，明确转换 |
| 力 | `N` | 力和质量不可混用 |
| 压力 | `Pa` | 记录表压或绝对压 |
| 电压、电流 | `V`、`A` | 明确直流、交流和量程 |
| 能量、功率 | `J`、`W` | 记录采样窗口和积分口径 |
| 浓度 | `mol/L` 或明确质量浓度 | 记录溶剂、温度和测量口径 |

- 变量、字段或类型必须体现单位，例如 `timeout_ms`、`angle_rad`、`sample_rate_hz`、`distance_m`。
- 禁止无说明的 `value`、`time`、`angle`、`size` 等跨边界字段。
- 单位转换只在模块边界或专用转换函数完成；内部统一一种单位，避免同一字段在流程中反复转换。
- 转换必须明确精度、舍入、溢出、上下限和非法值处理；不能依赖隐式类型转换。
- 存储和接口文档中的单位、精度和有效范围必须与代码类型一致。

## 3. 数值精度与特殊值

- 选择能覆盖业务范围和误差预算的类型；嵌入式和协议字段优先使用明确宽度的整数或浮点类型。
- 浮点比较使用任务允许的绝对误差、相对误差或单位化阈值，不直接比较相等。
- `NaN`、正负无穷、溢出、下溢和缺失值必须有明确编码；不能把零当作缺失。
- 传输或持久化前确认字节序、缩放因子、定点格式、符号位和范围；恢复后检查结果不超界。
- 标定、量化和滤波记录参数、版本、输入单位和误差影响。

## 4. 坐标系与姿态

项目默认使用右手坐标系。每个坐标系必须有稳定名称、原点、轴方向、单位、父坐标系和有效时间范围。

推荐命名：

```text
world      # 全局或实验参考系
map        # 可定位地图参考系
odom       # 连续里程计参考系
base_link  # 机器人主体参考系
imu        # IMU 传感器系
camera     # 相机光学或设备系，需明确轴方向
tool       # 末端工具系
```

- 默认约定为 `x` 前、`y` 左、`z` 上；设备原生坐标不同，必须在适配层转换并记录来源。
- 坐标系名称不可复用表示不同含义；传感器安装方向改变时生成新的标定版本。
- 姿态统一使用项目约定的四元数分量顺序；默认文档写明为 `x, y, z, w`，不得只写四个无名数字。
- 同时使用欧拉角时，必须说明旋转顺序、内禀或外禀、角度单位和万向节锁风险。
- 变换必须说明方向，例如 `T_parent_child` 表示 child 坐标中的点变换到 parent 坐标；禁止仅用 `transform`。
- 姿态、速度、加速度和协方差必须标注所在坐标系；协方差不能跨坐标系直接复制。
- 变换链必须无环；缺少父变换、标定过期或时间不匹配时返回可识别错误，不使用静默的单位阵替代。

## 5. 标定与坐标变换

标定文件至少记录设备、硬件序列或匿名 ID、坐标系名称、内参或外参、标定方法、采集日期、有效范围、误差指标、工具版本、校准人和文件校验和。

- 标定数据与固件、设备配置、数据集和模型版本绑定。
- 温度、负载、焦距、安装位置或机械结构变化可能使标定失效；应定义重新标定条件。
- 变换函数检查输入维度、有限值、单位和时间；不接受未知坐标系。
- 记录转换前后坐标系和时间戳，便于日志和实验结果回溯。

## 6. 时间语义

同时区分以下时间：

| 时间 | 含义 | 用途 |
| --- | --- | --- |
| `source_time` | 传感器或外部设备采样时间 | 对齐数据和测量延迟 |
| `event_time` | 事件实际发生时间 | 状态机和行为记录 |
| `received_at` | 本模块收到数据的时间 | 排查通信和队列延迟 |
| `processed_at` | 本模块完成处理的时间 | 处理耗时和吞吐 |
| `timestamp` | 日志事件时间，使用 UTC | 跨模块检索和审计 |
| `monotonic_time` | 单调时钟读数 | 计算持续时间和超时 |

- 墙上时间用于展示和跨设备关联；持续时间、超时和调度间隔必须使用单调时钟。
- 跨进程、跨设备和存储接口的时间戳使用 UTC RFC 3339 或明确宽度的 UTC epoch，并在字段名中说明精度。
- 不得把本地时间、时区偏移或格式化字符串当作机器比较的唯一时间。
- 采样时间、接收时间和处理时间不能互相覆盖；延迟至少可计算为 `received_at - source_time`（在时钟已同步或已校正时）。
- 时间戳必须携带来源时钟、精度、同步状态或误差估计（适用时）。

## 7. 时钟同步与数据对齐

- 项目为每类系统指定时钟权威和同步方式；可用 NTP、PTP、GNSS、硬件触发或设备协议，但不得假定所有设备自动同步。
- 记录时钟偏移、漂移、同步时间、同步状态和估计误差；同步失败时禁止静默拼接数据。
- 传感器融合、控制和实验对齐定义允许的最大偏差、抖动、乱序、重复和丢帧行为。
- 数据对齐使用明确策略：最近邻、线性插值、保持、丢弃或等待；记录窗口、插值边界和缺失状态。
- 未来时间、过旧数据、时钟回拨和超出窗口的数据必须触发告警或确定性丢弃，不能导致负延迟或倒序状态。
- 关键控制环路使用硬件时间戳或单调时钟，并把同步误差纳入安全和稳定性预算。

## 8. 接口、存储与日志

- [接口文档规范](api-documentation.md) 的字段表必须写明单位、坐标系、时间基准、精度和有效范围。
- JSON、数据库和消息字段使用完整名称，例如 `timestamp_utc`、`duration_ms`、`pose_base_link`，不依赖上下文猜测。
- 日志遵循 [日志与终端输出规范](logging.md)：使用 UTC 时间记录事件，使用单调时钟计算耗时，并记录源时间与接收时间（适用时）。
- 数据集清单记录单位、坐标系、标定版本、采样率、时钟来源和同步误差，遵循 [数据与实验规范](data-experiment.md)。
- 不得在日志、接口或文件中同时出现同名但不同单位或参考系的字段。

## 9. 测试与验证

至少验证：单位转换、边界与溢出、精度和舍入、非法单位、坐标轴方向、变换逆运算、四元数归一化、变换链缺失、标定版本、时间回拨、时钟偏移、漂移、乱序、重复、丢帧、过期数据和同步失败。

- 使用已知点、已知姿态和可计算的时间序列作为确定性测试夹具。
- 对多坐标系和多设备测试同时记录硬件、标定、时钟和数据版本。
- 控制和安全相关变换必须进行仿真、硬件在环或受控实机验证，不能只凭单元测试。
- 验证命令和未覆盖范围遵循 [验证规范](verification.md)；代码 Review 必须按 [代码 Review 规范](code-review.md) 检查并报告单位、坐标系和时间风险。
