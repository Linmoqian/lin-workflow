# 数据与实验规范

## 1. 适用范围

本规范适用于生物数据、传感器数据、机器人采集数据、标注数据、实验记录、数据处理流水线及其派生结果。

数据和实验结果必须能够回答：数据从哪里来、经过什么处理、由哪个版本的代码生成、使用了什么环境和参数、结果是否可以复现。原始数据、派生数据、实验记录和发布结果必须分层管理，不得混为一个可覆盖的目录。

## 2. 数据分层与目录

推荐按数据集或实验主题归档；同一数据集的清单、处理记录和说明放在同一主题目录。原始数据不得直接提交 Git。

```text
data/
├── raw/             # 原始采集，只读，不覆盖
├── interim/         # 清洗或转换中的中间数据
├── processed/       # 可复用的标准化数据
├── annotations/     # 标注及标注版本
├── derived/         # 分析、特征和模型派生数据
└── manifests/       # 数据清单、血缘和质量报告
```

- 若项目不适合在仓库保存数据，以上目录只保留说明、清单和获取脚本，真实数据存放在受控存储中。
- 每个数据集指定一个不可变的 `dataset_id` 和版本；禁止用 `latest` 代替版本。
- 原始数据只读保存。修正采集错误时生成新版本并保留原始文件、原因和修正记录。
- 受试者、设备、实验批次和文件使用稳定匿名标识，不在文件名或路径中放置姓名、手机号、身份证号等直接身份信息。
- 数据文件、清单、实验报告和代码均使用项目日期命名规范；同一数据集的派生物保留相同主题和来源版本。

## 3. 数据清单与最小元数据

每个可复用数据集必须有清单（推荐 JSON 或 YAML），至少记录：

| 字段 | 要求 |
| --- | --- |
| `dataset_id`、`version` | 稳定标识和不可变版本 |
| `source` | 来源、采集方式、授权或许可证 |
| `collection_window` | 开始、结束时间及时间基准 |
| `subject_or_device_ids` | 匿名样本、设备或实验批次标识 |
| `schema` | 字段、类型、必填性、枚举和版本 |
| `units`、`coordinate_frame` | 数值单位、坐标系和变换约定 |
| `sampling` | 采样率、触发方式、丢样规则和数据量 |
| `software`、`hardware` | 采集程序、固件、设备、驱动和配置版本 |
| `checksums` | 文件或对象校验和、大小和生成时间 |
| `quality` | 缺失、重复、异常、漂移和批次质量摘要 |
| `lineage` | 输入版本、处理步骤、代码提交和运行标识 |
| `retention`、`access` | 保留期限、访问范围和删除策略 |

字段含义、单位、时间基准和坐标系必须与 [接口文档规范](api-documentation.md) 及 [单位、坐标系与时间规范](units-coordinate-time.md) 一致。

## 4. 数据血缘

每次生成中间数据、特征、标注或实验结果，都必须记录一份运行清单。最小记录包括：

- 输入数据集版本及每个输入文件的校验和。
- 输出数据集版本及输出文件校验和。
- 处理代码的 Git 提交、脚本路径和依赖锁文件。
- 运行环境、操作系统、编译器或解释器、硬件和关键驱动版本。
- 配置文件、命令行参数、随机种子、并发配置和时区。
- 开始时间、结束时间、耗时、日志关联 ID 和成功或失败状态。
- 过滤、插值、归一化、重采样、标注修订和异常剔除的原因。

处理步骤应组成有向链：输入 → 转换 → 质量检查 → 输出。禁止直接覆盖上一步结果或在没有记录的情况下手工修改派生数据。手工修订必须有修订人、时间、原因、影响范围和前后校验和。

## 5. 采集与实验设计

实验开始前记录问题、假设、主要终点、次要终点、对照、样本或试验单元、纳入和排除条件、预期样本量、随机化或分组方法、盲法（如适用）及统计方法。

- 实验协议、设备配置、校准状态和环境条件必须版本化。
- 正式实验使用明确的实验运行 ID；同一运行 ID 不得复用于不同配置。
- 对照组、阳性或阴性对照、空白样本和重复测量应按任务需要设置，并在记录中说明缺失原因。
- 失败实验、异常批次和未达到预设条件的运行不得静默删除；标记状态并记录原因。
- 采集时间、设备时间、处理时间和发布时间分开记录，禁止把处理时间当作样本时间。
- 关键设备在采集前后执行校准或自检；校准文件与数据集版本绑定。

## 6. 数据质量与统计

进入分析或训练前必须执行与数据类型匹配的质量检查：文件完整性、格式和 schema、缺失率、重复、范围、单位、时间连续性、坐标系、采样率、传感器饱和、异常值、批次差异和标签一致性。

- 质量检查输出机器可读结果和人工可读摘要；每个样本或批次有明确的 `pass`、`warn` 或 `fail` 状态。
- 异常值不能只凭视觉删除；必须定义判定规则、保留原值并记录处理方式。
- 缺失值、插值、平滑、归一化和批次校正必须记录方法、参数和适用范围。
- 统计结论说明样本单位、有效样本数、排除数量、效应量、不确定性和适用边界；不只报告均值。
- 多次试验、多个受试者或多个设备时，说明独立性、重复测量和批次效应的处理方法。
- 未达到质量门槛的数据进入隔离区，不得被下游脚本默认读取。

## 7. 生物数据、伦理与隐私

涉及人类、动物、遗传、健康、行为、生理或生物识别数据时，必须在采集前确认适用的伦理审批、知情同意、数据使用目的和共享范围。没有授权依据的数据不得采集、导入或用于训练。

- 直接标识符与研究数据分离保存；映射表使用单独的访问控制和审计。
- 使用最小化原则，只保存任务所需字段；不因调试方便保存完整原始身份信息。
- 导出、共享和训练前执行去标识化、泛化、匿名化或受控访问评估，并记录风险。
- 日志、终端、异常、截图、样例、测试夹具和 Review 报告不得包含可识别生物数据。
- 生物数据的删除、撤回、保留期限和备份清理必须可执行并有记录。
- 访问权限按角色和项目隔离；下载、导出、批量查询和权限变更记录审计事件。
- 若数据无法充分匿名化，必须限制访问、禁止外发，并在文档中明确未解决的再识别风险。

## 8. 实验复现

实验结果交付时必须同时提供结果摘要、运行清单、配置、输入数据版本、代码提交、环境和验证命令。任何人仅凭这些材料应能复现主要结果，或明确知道无法复现的原因。

推荐最小文件集合：

```text
YYYY-MM-DD-experiment-name/
├── protocol.md
├── run-manifest.json
├── config/
├── results/
├── reports/
└── README.md
```

- `README.md` 说明入口命令、前置条件、数据获取方式和预期输出。
- 结果文件不得只存图；保留生成图表所需的结构化数据和统计脚本。
- 随机实验至少固定并记录主随机种子；并行执行时记录工作线程或进程的种子派生方式。
- 环境不可复现时，记录实际版本、差异、影响评估和替代验证结果，不得声称完全复现。

## 9. 安全、成本与保留

- 原始数据、凭证、授权文件和受限数据不提交 Git，不写入镜像或构建产物。
- 大文件使用项目批准的存储和清单机制；下载脚本必须校验来源、版本和校验和。
- 数据访问、传输和备份使用受控权限和加密；共享链接设置过期和最小范围。
- 保留期限、备份、归档和删除策略按数据敏感级别确定；删除前确认不会破坏必要的血缘证据。
- 数据处理失败、空间不足、校验失败和权限拒绝应使用 [日志与终端输出规范](logging.md) 记录可回溯事件，但不得记录敏感载荷。

## 10. 测试、验证与 Review

数据和实验流水线至少验证：空数据、单样本、边界值、缺失、重复、单位错误、时间回拨、坐标系错误、损坏文件、权限拒绝、版本不兼容、随机种子复现和重复运行一致性。

验证记录实际命令、数据版本、环境、硬件、结果和未覆盖范围，遵循 [验证规范](verification.md)。

Review 必须检查数据血缘是否完整、原始数据是否可追溯、数据划分是否泄漏、隐私与伦理依据是否存在、质量门槛是否生效、实验失败是否保留以及结果是否可复现，并按 [代码 Review 规范](code-review.md) 生成报告。
