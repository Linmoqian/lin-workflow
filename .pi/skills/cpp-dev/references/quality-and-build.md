# C++ 质量、构建与检查细则（cpp-dev references）

## 10. 并发、日志与安全

遵循 [并发与线程](../../concurrency/SKILL.md) 和 [日志与终端输出](../../logging-terminal/SKILL.md)：

- 默认单线程；引入线程、线程池、协程或并行算法前定义目标并用基准证明收益。
- 线程、队列、重试、缓存和任务数量必须有界；禁止不可回收的 `detach` 线程。
- 锁范围最小，锁内禁止阻塞 I/O、回调、长计算和未知外部调用；多锁规定统一顺序。
- 使用统一日志适配器记录组件、事件、操作 ID、阶段、结果、错误码和耗时。
- 不在锁内、实时线程、ISR、析构函数和不允许阻塞的路径执行日志 I/O。
- 高频日志限频、采样或汇总；日志入口执行敏感信息脱敏和多行转义。
- 禁止缓冲区越界、Use-after-free、Double-free、数据竞争、整数溢出和未定义行为。
- 外部命令、动态库、插件和反序列化采用允许列表和最小权限；不执行字符串拼接命令或 SQL。

## 11. 构建与依赖

遵循 [CMake 规范](../../cmake/SKILL.md)：

- 使用 target 级配置，依赖明确标记 `PRIVATE`、`PUBLIC` 或 `INTERFACE`。
- 第三方依赖使用锁定版本或可复现来源，记录用途、许可证和平台兼容性。
- 构建必须支持项目需要的 Debug、Release 和 Sanitizer 配置；生成文件、缓存和临时日志不得提交。
- CMake 配置失败、警告或生成器不一致不得被脚本静默忽略。

## 12. 静态检查、Sanitizer 与测试

- 按目标平台启用 `clang-format`、`clang-tidy`、`cppcheck` 和 MSVC `/analyze` 等可用检查。
- 按风险启用 AddressSanitizer、UndefinedBehaviorSanitizer、ThreadSanitizer；Sanitizer 不能替代硬件和平台测试。
- 单元测试覆盖领域逻辑、边界和错误；集成测试覆盖文件、网络、设备和跨语言边界。
- 并发测试使用屏障、条件变量、测试时钟和可控信号，不依赖固定睡眠或偶然调度。
- 性能承诺必须记录硬件、编译器、构建类型、数据规模和并发配置。
- 提交前按项目实际支持的 preset 或命令执行配置、构建、测试、格式化和静态检查，并如实记录未覆盖范围。

## 13. Review 检查项

Review C++ 改动时至少检查：

- 是否先读取本规范及直接相关专题规范。
- 模块依赖、公共头文件和 API/ABI 是否清晰稳定。
- 所有权、RAII、移动/复制语义、生命周期和异常安全是否明确。
- 是否存在裸内存管理、悬空引用、未定义行为、越界、数据竞争或整数溢出。
- 线程、锁、任务取消、超时和关闭生命周期是否安全。
- CMake target、依赖、警告、Sanitizer、静态检查和测试是否覆盖风险。
- 日志是否可回溯、有限频、可脱敏且不会阻塞关键路径。
- 每次 Review 后按 [代码 Review 规范](../../code-review/SKILL.md) 生成日期命名报告。
