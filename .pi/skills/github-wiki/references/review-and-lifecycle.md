# Wiki Review、复审与生命周期（github-wiki references）

## 10. Review 与发布前检查

Wiki 页面发布前至少检查：

- 内容与当前代码、配置、测试、发行版本和主仓库权威文档一致。
- 页面已加入 `Home`、`_Sidebar` 或相关页面，且不存在孤立入口。
- 命令、路径、版本号、环境变量和权限要求准确，能够在声明的环境中复现。
- 链接、代码块、表格、图片、替代文本和 Markdown 渲染正常。
- 没有 Token、API Key、密码、私钥、证书、个人信息、内部地址、未公开漏洞细节或未授权实验数据。
- 已标注适用版本、维护人、最后复审日期、已知限制和未验证项。
- 没有与现有页面重复、冲突、过时或无法维护的内容。
- 涉及安全、API、发行、硬件、机器人或实验流程时，已由对应领域负责人专项审查。

## 11. 更新、完善与复审

以下事件发生时必须更新相关 Wiki 页面：

- 代码、配置、API、依赖、工具链或部署流程变化。
- 新版本发布、兼容性变化、迁移方案或回滚策略变化。
- Issue、Review 或用户反馈发现错误、歧义或缺失步骤。
- 安全事件、隐私要求或权限边界变化。
- 页面达到复审周期；默认每季度复审一次，安装、部署、API 和安全页面应在相关变更后立即复审。

每次复审至少更新最后复审日期、适用版本、页面状态、变更摘要和已知限制。重大更新应保留 Wiki Git 提交历史，并在主仓库任务、Release 或变更日志中留下关联记录。

## 12. 弃用、归档与恢复

- 过时页面不得直接删除；先标记为 `已弃用` 或 `已归档`，说明原因、生效日期和替代页面。
- 从主导航移除归档页面，但保留历史链接、迁移说明和必要背景。
- 已归档页面不得被新页面作为现行操作依据引用。
- 只有法律、安全、隐私或凭据泄露等必须删除的情况，才可彻底移除页面；删除前必须获得工程师确认并记录原因、范围和恢复依据。
- 定期导出或保留 Wiki 源文件，避免独立 Wiki 仓库成为唯一备份。

## 13. 版本绑定与发行

- 安装、部署、API、迁移、兼容性和回滚页面应在对应版本发布前完成复审。
- 版本绑定页面必须关联 Git Tag、GitHub Release、适用版本、验证结果和已知限制。
- Wiki 发布不能代替 GitHub Release；正式发行仍遵循 [GitHub 规范](../../github-workflow/SKILL.md) 的 Tag、制品和发布确认流程。
- 已发布版本的 Wiki 历史不得被改写为不兼容的内容；发现错误时追加修正记录并指向安全版本。
