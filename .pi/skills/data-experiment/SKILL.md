# 数据与实验规范

## 1. 适用范围

本规范适用于生物数据、传感器数据、机器人采集数据、标注数据、实验记录、数据处理流水线及其派生结果。

数据和实验结果必须能够回答：数据从哪里来、经过什么处理、由哪个版本的代码生成、使用了什么环境和参数、结果是否可以复现。原始数据、派生数据、实验记录和发布结果必须分层管理，不得混为一个可覆盖的目录。

## 2. 数据分层与目录

推荐按数据集或实验主题归档；同一数据集的清单、处理记录和说明放在同一主题目录。原始数据不得直接提交 Git。

```text
data/
├── raw/             # 原始采集，只读，不覆盖
├── interim/         # 清洗或转换中的中间数据
├── processed/       # 可复用的标准化数据
├── annotations/     # 标注及标注版本
├── derived/         # 分析、特征和模型派生数据
└── manifests/       # 数据清单、血缘和质量报告
```

- 若项目不适合在仓库保存数据，以上目录只保留说明、清单和获取脚本，真实数据存放在受控存储中。
- 每个数据集指定一个不可变的 `dataset_id` 和版本；禁止用 `latest` 代替版本。
- 原始数据只读保存。修正采集错误时生成新版本并保留原始文件、原因和修正记录。
- 受试者、设备、实验批次和文件使用稳定匿名标识，不在文件名或路径中放置姓名、手机号、身份证号等直接身份信息。
- 数据文件、清单、实验报告和代码均使用项目日期命名规范；同一数据集的派生物保留相同主题和来源版本。

- 数据清单与元数据、血缘、采集与实验设计、质量统计：[data-lifecycle.md](references/data-lifecycle.md)，设计采集或整理数据时读。
- 伦理与隐私、复现、保留策略、测试与 Review：[ethics-and-reproducibility.md](references/ethics-and-reproducibility.md)，处理生物数据或归档时读。
