# 数据生命周期细则（data-experiment references）

## 3. 数据清单与最小元数据

每个可复用数据集必须有清单（推荐 JSON 或 YAML），至少记录：

| 字段 | 要求 |
| --- | --- |
| `dataset_id`、`version` | 稳定标识和不可变版本 |
| `source` | 来源、采集方式、授权或许可证 |
| `collection_window` | 开始、结束时间及时间基准 |
| `subject_or_device_ids` | 匿名样本、设备或实验批次标识 |
| `schema` | 字段、类型、必填性、枚举和版本 |
| `units`、`coordinate_frame` | 数值单位、坐标系和变换约定 |
| `sampling` | 采样率、触发方式、丢样规则和数据量 |
| `software`、`hardware` | 采集程序、固件、设备、驱动和配置版本 |
| `checksums` | 文件或对象校验和、大小和生成时间 |
| `quality` | 缺失、重复、异常、漂移和批次质量摘要 |
| `lineage` | 输入版本、处理步骤、代码提交和运行标识 |
| `retention`、`access` | 保留期限、访问范围和删除策略 |

字段含义、单位、时间基准和坐标系必须与 [接口文档规范](../../api-documentation/SKILL.md) 及 [单位、坐标系与时间规范](../../units-coordinate-time/SKILL.md) 一致。

## 4. 数据血缘

每次生成中间数据、特征、标注或实验结果，都必须记录一份运行清单。最小记录包括：

- 输入数据集版本及每个输入文件的校验和。
- 输出数据集版本及输出文件校验和。
- 处理代码的 Git 提交、脚本路径和依赖锁文件。
- 运行环境、操作系统、编译器或解释器、硬件和关键驱动版本。
- 配置文件、命令行参数、随机种子、并发配置和时区。
- 开始时间、结束时间、耗时、日志关联 ID 和成功或失败状态。
- 过滤、插值、归一化、重采样、标注修订和异常剔除的原因。

处理步骤应组成有向链：输入 → 转换 → 质量检查 → 输出。禁止直接覆盖上一步结果或在没有记录的情况下手工修改派生数据。手工修订必须有修订人、时间、原因、影响范围和前后校验和。

## 5. 采集与实验设计

实验开始前记录问题、假设、主要终点、次要终点、对照、样本或试验单元、纳入和排除条件、预期样本量、随机化或分组方法、盲法（如适用）及统计方法。

- 实验协议、设备配置、校准状态和环境条件必须版本化。
- 正式实验使用明确的实验运行 ID；同一运行 ID 不得复用于不同配置。
- 对照组、阳性或阴性对照、空白样本和重复测量应按任务需要设置，并在记录中说明缺失原因。
- 失败实验、异常批次和未达到预设条件的运行不得静默删除；标记状态并记录原因。
- 采集时间、设备时间、处理时间和发布时间分开记录，禁止把处理时间当作样本时间。
- 关键设备在采集前后执行校准或自检；校准文件与数据集版本绑定。

## 6. 数据质量与统计

进入分析或训练前必须执行与数据类型匹配的质量检查：文件完整性、格式和 schema、缺失率、重复、范围、单位、时间连续性、坐标系、采样率、传感器饱和、异常值、批次差异和标签一致性。

- 质量检查输出机器可读结果和人工可读摘要；每个样本或批次有明确的 `pass`、`warn` 或 `fail` 状态。
- 异常值不能只凭视觉删除；必须定义判定规则、保留原值并记录处理方式。
- 缺失值、插值、平滑、归一化和批次校正必须记录方法、参数和适用范围。
- 统计结论说明样本单位、有效样本数、排除数量、效应量、不确定性和适用边界；不只报告均值。
- 多次试验、多个受试者或多个设备时，说明独立性、重复测量和批次效应的处理方法。
- 未达到质量门槛的数据进入隔离区，不得被下游脚本默认读取。
