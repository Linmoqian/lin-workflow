# 通用写作规范

使用本 Skill 完成项目内写作与文档改动。将仓库根目录视为本文件的三级父目录。

## 读取规范

1. 先阅读 [写作规范](../../../docs/development/writing.md)。
2. 涉及代码、接口或测试文档时，再读取对应专题规范。
3. 仅在需要交付 LaTeX 或 PDF 时，阅读 [LaTeX 专项参考](references/latex.md)。

## 目录管理

- 按文档主题或交付物建立目录；同一文档的 `.md`、`.tex`、`.pdf` 与 `assets/` 必须位于同一目录。
- 目录和文件名使用小写 kebab-case；文档文件名以 `YYYY-MM-DD-主题名.扩展名` 开头，例如 `2026-08-24-release-notes.md`。不使用空格、中文、下划线、混合大小写或 `latest` 等模糊日期。
- 主文件使用相同的日期和主题名；不创建空目录、空文件或按格式分散的全局 `md/`、`tex/`、`pdf/` 目录。
- 每份文档指定唯一可编辑的权威源，默认 Markdown；以 `.tex` 为准时不得双向同步。确需 PDF 时才增加 LaTeX 源码和 PDF，并保持 PDF 可由同目录源文件生成。

## 工作流程

1. 明确文档目标、读者、载体、范围和交付格式；信息不足且会影响结论时先询问。
2. 先组织结论与结构，再写正文；事实、数据、引用、命令和链接必须可追溯。
3. 使用语义化标题、表格、代码块、图注和替代文本；不以堆砌格式代替内容。
4. 完成后检查术语一致性、链接、示例、图表、引用和可复现步骤；仅报告实际验证结果。

## 文档解析与格式转换

- 复杂 PDF、扫描件、Office、表格、公式或多栏文档优先使用 MinerU 官方 API；简单文本或 MinerU 不可用时使用 MarkItDown 等现有工具。
- 解析前确认授权、隐私和版权边界；记录源文件校验和、解析器/模型版本、任务 ID、输入输出格式和结果校验和。
- MinerU 缺少 Token/API Key、权限或配额时向工程师请求；不得把密钥写入仓库、文档、命令输出或日志。
- 学术文献检索优先使用 SciVerse，并保留查询、文献标识、证据片段和来源位置；关键结论核验原始来源。

## LaTeX 与 PDF

- PDF 不是所有文档的默认交付物；仅在读者、模板或发布渠道需要时使用 LaTeX。
- 优先复用项目、学校、期刊或客户已有模板；不自动迁移源文件、创建追踪清单或清理辅助文件。
- 默认使用 XeLaTeX。编译前确认图片路径、字体与现有构建脚本，编译后核验 PDF 和关键页面。

## 交付

最终说明文档路径、目标读者、实际核验方式和未覆盖风险。涉及 PDF 时额外说明 `.tex`、PDF 与图片资产的位置。
