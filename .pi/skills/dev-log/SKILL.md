# 开发日志规范

## 1. 定位与边界

- 开发日志是开发过程的流水记录：做了什么、为什么这么做、遇到什么问题、留下什么风险。
- 与其他记录的边界：
  - `TODO.md` 是任务清单，只记待办与完成状态，不展开过程。
  - Git 提交信息概括一次改动的目的，不承载决策背景与排查过程。
  - `MEMORY.md` 只存长期有效的决策与约束；日志按时间流水，过期不删改。
- 日志只追加，不回改历史条目；写错了新起一条更正，注明更正对象。

## 2. 载体与选择

两种载体二选一，同一时段保持一致，不把同一条内容双写：

| 载体 | 文件 | 适用 |
| --- | --- | --- |
| log | `docs/logs/YYYY-MM-DD.log`，一天一文件 | 日常随手记录，轻量、可读性优先 |
| CSV | `docs/logs/YYYY-MM.csv`，一月一文件 | 需要结构化检索、月度回顾、耗时与类型统计 |

默认用 log；工程师明确要求或需要表格分析时用 CSV。`docs/logs/` 在第一条日志写入时创建，并附带简短 `README.md`（用途与格式速查）。

## 3. log 格式

一行一条，追加到当日文件：

```text
[HH:MM] TYPE | module | summary
```

- `TYPE` 见第 5 节枚举。
- `module` 是涉及的模块或目录，如 `marketplace`、`.pi/agents`；跨模块写 `misc`。
- `summary` 一句话说明事实；决策写清选项与理由，问题写清现象与结论。
- 可选续行：以两个空格缩进开头，归属上一条。

示例：

```text
[14:05] FEAT | marketplace | install.ps1 支持 claude 目标，工具名映射 pi->Claude
[14:20] DECISION | marketplace | 子代理转换不迁移 tools 白名单，Claude 无文件级对应
[15:02] ISSUE | .pi/agents | worker 改写出现"暂停并暂停执行"叠加，整句规则修复
```

## 4. CSV 格式

UTF-8 编码，首行为表头，逗号分隔，字段内含逗号或引号时按 RFC 4180 转义（双引号包裹、内部双引号翻倍）：

```csv
date,time,type,module,summary,ref
2026-10-03,14:05,feat,marketplace,install.ps1 支持 claude 目标,a2585a6
2026-10-03,14:20,decision,marketplace,子代理转换不迁移 tools 白名单,
2026-10-03,15:02,issue,.pi/agents,worker 改写叠加 bug 整句规则修复,
```

- `date` 用 `YYYY-MM-DD`，`time` 用 24 小时制 `HH:MM`。
- `ref` 选填：关联的提交哈希、Issue 编号或文件路径。
- 新月份创建新文件，复制表头。

## 5. 类型枚举

| TYPE | 含义 |
| --- | --- |
| FEAT | 完成一个功能或阶段性工作 |
| FIX | 修复问题，summary 记根因与修法 |
| DECISION | 做出决策，记选项与理由 |
| ISSUE | 遇到问题或异常，记现象与结论 |
| RISK | 识别的风险，记触发条件与影响 |
| NOTE | 备忘、观察、待查证的信息 |

CSV 中 type 用小写（feat/fix/decision/issue/risk/note）。

## 6. 何时写

- 完成一个可验证的阶段性工作后（与提交同步，ref 填提交哈希）。
- 做出影响方案、接口、依赖或目录结构的决策后。
- 排查出问题根因、遇到阻塞或发现风险时，当场记，不等任务结束。
- 会话结束前补齐当天未记录的关键事件。

不写：纯想法未落地的内容、重复 TODO 的待办、敏感信息（密钥、账号、内部地址）。

## 7. Agent 代写规则

- 按工程师当前指示选择载体；未指定时延续 `docs/logs/` 中最近使用的载体。
- 记录采用工程师口吻的事实描述，不写自我评价；一条一行，不重排历史。
- 日志写入不算改动验证，不需要随日志提交；与代码改动同批提交时在提交信息保持一句话概括。
- 需要回顾时按日期或月份读取对应文件，引用条目附原始时间戳。
