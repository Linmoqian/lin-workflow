# 接口文档固定格式（api-documentation references）

## 3. 固定文档格式

接口文档统一使用 Markdown，并严格按以下顺序使用二级标题；没有内容的可选章节应写明“不适用”或按模板说明省略，禁止任意改名造成检索困难：

1. `接口元信息`
2. `请求`
3. `响应`
4. `错误码`
5. `权限与安全`
6. `行为约束`
7. `调用示例`
8. `兼容性与变更记录`

文档一级标题使用接口名称。三级标题只用于区分请求示例、响应示例、事件、channel 或同一接口的明确子项，不得跳级。

### 3.1 接口元信息表

通用元信息必须包含：

| 项目 | 内容 |
| --- | --- |
| 接口标识 | 稳定且唯一的 command、事件名称或 `METHOD /path` |
| 用途 | 一句话描述接口解决的问题 |
| 调用方 | 前端模块、外部系统或其他明确调用者 |
| 提供方 | Tauri 后端或后端服务 |
| 稳定性 | 实验性、稳定或已废弃 |
| 引入版本 | 首次可用的应用或 API 版本 |
| 维护方 | 负责该契约的模块或团队 |

Tauri IPC 还必须记录接口类型（command、事件或 channel）、同步或异步方式，以及 capability/permission。HTTP API 在技术选型完成后还必须记录所属环境、Base URL、Method、Path、认证方式、请求与响应 `Content-Type`。

### 3.2 字段表

请求字段统一使用：

| 字段 | 位置 | 类型 | 必填 | 默认值 | 约束 | 说明 |
| --- | --- | --- | --- | --- | --- | --- |
| `<名称>` | `<IPC/path/query/header/body>` | `<类型>` | `<是/否>` | `<值或—>` | `<范围、格式、枚举、长度、单位>` | `<语义>` |

响应字段统一使用：

| 字段 | 类型 | 必定返回 | 约束 | 说明 |
| --- | --- | --- | --- | --- |
| `<名称>` | `<类型>` | `<是/否>` | `<范围、格式、枚举、单位>` | `<语义>` |

嵌套对象使用点号路径，如 `data.id`；数组元素使用 `items[].id`。字段类型应使用接口边界实际暴露的类型，不使用仅实现内部可见的 Rust 或 TypeScript 类型名代替契约说明。

### 3.3 错误码表

| 代码 | 含义 | 可重试 | 处理建议 |
| --- | --- | --- | --- |
| `<稳定错误码或 HTTP 状态>` | `<触发条件>` | `<是/否/满足条件>` | `<调用方动作>` |

错误码必须稳定且可区分。需要重试时说明退避、最大次数或服务端提示的优先级；不得建议无上限重试。HTTP 错误同时记录状态码和业务错误码（如存在）。
