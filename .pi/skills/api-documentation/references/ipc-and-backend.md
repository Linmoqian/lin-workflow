# Tauri IPC 与后端 API 专项（api-documentation references）

## 5. Tauri IPC 专项要求

- command 文档必须记录准确名称、输入 DTO、输出 DTO、同步或异步方式和稳定错误结构。
- command 只承诺 IPC 边界类型；领域内部类型不得被当作公开契约。
- 事件必须记录事件名、发送方、接收方、触发时机、载荷、频率、是否可能重复或丢失，以及取消订阅方式。
- channel 必须记录载荷、消息顺序、完成与错误信号、背压或流量限制，以及调用方取消和资源回收方式。
- 涉及长任务时必须说明超时、取消、应用重启后的行为和进程内状态是否丢失。

## 6. 后端 API 专项要求

后端 API 技术选型确认后，每个 HTTP 接口还必须说明：

- 环境与 Base URL，以及 `Method /path`。
- path、query、header、cookie 和 body 参数的位置与编码。
- 认证与授权、请求和响应 `Content-Type`、成功及错误状态码。
- 分页、过滤、排序、幂等键、限流、重试和缓存规则。
- 代理、网关或版本前缀对调用方可见时的稳定行为。

采用 Webhook 时，补充签名验证、重放防护、投递顺序、重试策略、超时和接收方幂等性。采用 WebSocket 时，补充握手认证、消息类型、顺序、心跳、断线重连、背压及关闭语义。未使用这些能力时无需添加对应章节。
