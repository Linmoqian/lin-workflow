# 接口文档规范

## 1. 适用范围

本规范覆盖前后端之间可调用或可订阅的公开契约，包括：

- Tauri command、事件与 channel。
- 后端 HTTP API，以及未来按需采用的 WebSocket、Webhook 等接口。

规范规则保存在本文件；实际接口文档按需保存在 `docs/api/`。没有实际接口时不创建空目录或占位文档。

当前未确定后端 API 的协议、框架和描述工具，不得由本规范擅自选择 REST、RPC、OpenAPI 版本或引入相关依赖；选型确认后再补充对应约束。

## 2. 编写原则

- 每篇文档描述一个职责明确的接口，或一组强相关接口；标题必须能直接定位契约。
- 文档必须说明调用方、稳定性和失败行为，不能只罗列请求与响应 JSON。
- 字段必须记录类型、必填性、默认值、约束、单位和含义；不适用时写 `—`，不得留空造成歧义。
- 示例必须脱敏、与字段定义一致并可直接用于对应环境；不得包含真实令牌、用户数据、内部地址或密钥。
- 简单接口不强制绘图；涉及多方参与、异步回调或复杂状态变化时，使用 Mermaid 时序图说明流程。
- 文档内容以对调用方可观察的契约为边界，不暴露无关的内部实现细节。

## 3. 必须描述的契约

### 请求与响应

- 请求字段记录位置、序列化格式、必填性、默认值、合法范围、格式、枚举和单位。
- 响应记录成功条件、完整字段、可空性及内容类型；HTTP API 还须列出所有预期状态码。
- 分页、过滤和排序必须说明参数、默认顺序、边界及游标或页码语义。

### 权限与安全

- 说明认证方式、授权范围、调用主体及拒绝访问时的行为。
- Tauri IPC 必须列出所需 capability/permission；未授权窗口或 WebView 不得隐式获得能力。
- 敏感字段必须标明是否可记录、存储、返回或展示，并说明脱敏要求。

### 行为约束

- 说明副作用、幂等性、重复调用结果以及必要的幂等键规则。
- 说明超时、取消、并发限制、限流、重试和失败后的资源状态。
- HTTP API 按需说明缓存键、有效期、失效条件及缓存相关响应头。
- 未定义的行为不得用示例暗示为稳定承诺。

### 兼容性

- 兼容变更包括新增可选字段、扩展允许值且旧调用方可继续工作的改动；调用方必须容忍文档明确允许扩展的字段。
- 删除或重命名字段、改变类型或语义、收紧约束、修改默认值及改变错误行为通常属于不兼容变更。
- 不兼容变更必须提供迁移方法、废弃标记、通知方式、废弃窗口和移除版本，不得无过渡直接替换稳定接口。

## 4. 事实来源与同步

- 实现代码、边界类型和接口文档必须在同一提交中同步更新，相关测试也必须随契约变化更新。
- Rust DTO、TypeScript 类型或后端 schema 是实现依据；接口文档是对调用方的稳定承诺，二者不一致时不得仅修改一侧后宣称完成。
- 使用生成文档时，必须声明生成源、生成命令和产物位置；生成文件不得手工修改。
- 变更记录只记录调用方可观察的契约变化，不复制 Git 提交日志。

## 5. 验证要求

- 契约测试覆盖正常请求、字段边界、错误结构和序列化结果。
- 权限测试覆盖允许与拒绝路径，不使用管理员或全权限环境掩盖权限缺陷。
- 不兼容变更必须验证迁移路径；兼容变更必须验证已有调用方仍可工作。
- 示例应通过测试、脚本或人工执行验证；无法执行时明确标记验证范围和原因。
- 复杂异步接口应覆盖重复、乱序、超时、取消和资源回收。
