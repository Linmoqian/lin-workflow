# 嵌入式运行时与安全细则（embedded-dev references）

## 3. 资源预算与内存

- 设计阶段建立 Flash、RAM、栈、堆、DMA 缓冲区、CPU 占用和功耗预算。
- 链接脚本、内存布局和 map 文件必须纳入构建产物检查。
- 默认使用静态或固定容量分配；启动后原则上禁止无界动态分配。
- 必须使用堆时，说明最大容量、生命周期、失败策略和碎片风险。
- 禁止递归、可变长栈对象和无上限容器；数组、队列和任务数量必须有上限。
- 每个任务配置独立栈，并在测试中检查栈水位和溢出保护。
- DMA 缓冲区满足对齐、地址范围、缓存一致性和生命周期要求。
- 超出资源预算必须阻止发布或形成明确例外记录。

## 4. 实时性与时序

- 为周期任务、中断、通信和启动流程定义截止时间、允许抖动和最大执行时间。
- 对关键路径测量最坏情况执行时间、调度延迟、中断延迟和队列等待时间，不以平均耗时代替实时性证明。
- 高优先级任务不得执行无界循环、阻塞 I/O、不可控日志或长时间临界区。
- 临界区、关中断和锁持有时间必须有上限；临界区内禁止调用未知耗时函数。
- 使用优先级继承、优先级天花板、单一所有者或消息传递避免优先级反转。
- 周期任务使用单调时间基准；超时、降级、丢帧和资源不足必须有确定行为。

## 5. 中断、线程与任务

ISR 只确认中断、读取必要状态、保存最小数据并投递事件，随后尽快退出。ISR 禁止动态分配、阻塞等待、获取不可立即获得的锁、复杂计算、慢速外设、协议解析、日志 I/O 和业务流程。

- 复杂处理转移到任务、工作队列或下半部，并定义事件丢失、合并和背压策略。
- 任务数量、优先级、栈大小、队列容量和周期必须有记录。
- 任务之间优先使用有界队列、事件或消息传递，减少共享可变状态。
- 不创建脱离生命周期管理的 detached 任务；每个任务必须有退出、取消、超时和回收路径。
- 关闭、升级或复位前停止接收新工作，并等待或取消已有任务。
- 遵循并发规范：线程数、队列容量和重试次数必须有上限。

## 6. 硬件抽象与驱动

- 外设初始化、配置、读写、错误和复位路径封装在驱动或 HAL 中。
- 寄存器访问使用统一类型、`volatile` 语义、内存屏障和读改写策略。
- 不使用未经说明的魔数；寄存器位、时钟、引脚和中断号使用命名常量或配置。
- 驱动接口说明调用上下文：线程、ISR、初始化或低功耗唤醒。
- 明确设备状态：未初始化、就绪、忙、错误、恢复中和已停止。
- 外设异常、超时、拔插、时钟切换和电源变化必须可恢复或进入安全状态。
- 硬件依赖应可由 Mock、仿真器或测试适配层替换。

## 7. 启动、看门狗与故障恢复

启动流程明确记录：复位原因读取 → 时钟与内存初始化 → 安全默认状态 → 基础自检 → 驱动初始化 → 通信与存储恢复 → 应用启动 → 看门狗监管。

- 启动早期将执行器、继电器、功率和通信引脚置于安全默认状态。
- 初始化失败不得宣称系统就绪，应进入降级、维护或安全停机状态。
- 看门狗只能在系统健康检查通过后喂狗，禁止无条件喂狗掩盖死锁。
- 记录复位原因、固件版本、启动阶段和最近一次故障摘要。
- 任务卡死、栈溢出、堆损坏、非法访问、欠压和时钟异常必须有恢复策略。
- 复位循环限次并能进入安全或维护模式；关键故障信息使用带 CRC 和版本的持久化区域保存。
- 关键操作具备幂等性，避免复位后重复执行造成设备或数据损坏。

## 8. 持久化与掉电安全

- 持久化数据包含版本、长度、校验和必要的兼容标识。
- 配置更新使用双备份、日志式提交或原子交换，不能覆盖唯一有效副本后再假设写入成功。
- 明确擦除、写入、校验和提交各阶段掉电时的恢复行为。
- Flash、EEPROM 和 FRAM 写入考虑擦写寿命、磨损均衡和写入频率。
- 高频循环不得直接写非易失存储；采用缓存、批量提交或变化检测。
- 数据格式使用固定宽度类型和明确字节序，禁止直接持久化含指针或编译器布局依赖的对象。
- 格式变化同步更新版本迁移、测试和文档。
